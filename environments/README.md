# Isolated environment recipes

Three environment snapshots were exported from the installed source prefixes on 2026-10-29. `*.conda.explicit.txt` pins actual Linux x86-64 Conda package URLs; `*.pip.lock.txt` pins pip distributions and immutable VCS/wheel sources. `*.snapshot.json` records installed distributions and special build steps. No installed prefix is bundled.

Use `bin/vb env prepare --config configs/local.yaml`. The installer creates only configured prefixes, keeps logs under runtime/logs/environments, and resumes its own partially prepared prefixes. Explicit `environments.prefixes` entries reuse existing prefixes without installing into them; their import checks are still executed. An unowned preexisting default prefix is refused.

The default fixed-camera corpus does not use DPVO. Both source environments have DPVO, but the portable installer omits its optional native build and records that fact. Moving-camera operation is outside the tested package mode; it requires a separately built compatible DPVO/toolchain before use. Tactile Detectron2 is compiled from its locked commit; `environments.cuda_home` may select the target CUDA toolkit, and MAX_JOBS defaults to 2. WHAM ViTPose is built from a writable runtime copy of the bundled source, never from the frozen package tree. Legacy Chumpy is installed separately without build isolation.

Host prerequisites: Linux x86-64, working Conda executable, internet access to pinned Conda/Python/Git/wheel providers, compatible NVIDIA driver for selected Torch CUDA builds, compiler/toolkit for Detectron2, and disk space for installed dependencies/caches. The three Torch versions are deliberately separate. Clean environment creation has **not** been executed during source packaging; snapshots and existing-prefix import checks are evidence of existing installations, not clean-install proof. Actual target logs determine installation success.

The source-side inventory generator is not shipped as a destination setup command. Runtime preparation uses only the exported files and packaged module; original source-prefix strings in snapshot metadata are historical provenance.

Cold-build review fixes: WHAM torch-scatter2.0.9 and MMCV-full1.4.7 use official cp39/Torch1.11/CUDA11.3 wheels with complete remote-byte SHA256 verification; they do not fall back to an unconfigured source build. GVHMR PyTorch3D and torch-scatter retain matching cp310/Torch2.3/CUDA12.1 wheel pins plus installed-source SHA256. Prefix-specific PATH, library lookup and compiler variables avoid using the orchestrator's active environment. Locked NumPy/Cython/build tools are installed before Torch and before bulk source-package metadata compilation, and completed installations execute pip check. These corrections remove identified blockers; they do not substitute for a full clean-install test.
