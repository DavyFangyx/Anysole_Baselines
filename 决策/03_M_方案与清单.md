## 1. 定位与准入标准

M = **执行层优化**：算力 / 内存 / 时间开销下降，算法语义与数值精度不变。

**准入三条件（缺一不进 M）**：

1. **开销实测**：改动前后的速度 / 显存 / 迭代数对比表（同输入同机）；
2. **精度等价证据**：原生路径 vs 加速路径的数值 diff 表（同输入；如 GPU ICP 的 ~1e-6 级）；
3. **登记为"扩展"性质条目**（Baselines 仓库登记 + 一次提交 + 证据测试）：正式 baseline
   口径必须可开关——**正式复现跑 = 原生口径，M 开关只用于批量生产与迭代**。

M **不做**：模型结构、loss 公式、数据语义、评估口径改动（属 T / E 管辖）。

### 执行顺序（T1/T2 完成后）

```text
pressure_tookit（M1–M4，范例最成熟）→ FPP-Net（M12 + A3 随行）
  → Step2Motion（M8/M9）→ MotionPRO（M10/M11）→ PoseTransOpt（M5–M7）
  → 通用 M13 AMP 扫描
```

### 后续（按序，原 16 号 §3）

1. M13 终表（FPP 臂 + MotionPRO 计时复跑）→ bf16 各模型裁决。
2. M12 拍板 → 落 commit（batch 32 + TF32 关 + 开关化）。（已落地：Baselines cedd921、主仓 bf26da7）
3. M5–M10 其余条目（PoseTransOpt 并行/投影批量化/迭代截断、Step2Motion 早停/DDIM、MotionPRO batch 复核）按 §3 清单顺序推进。
4. depth 全量完成后：重跑 build_inputs → M1 全 session diff 补测 → pressure_tookit 正式全量生产。

## 6. 与 E 系列的分界（一句话）

M 只加速"跑出来"；E 只关心"跑出来的数字怎么比"。正式评估结果必须原生口径生成——M 开关打开的产物不进 E 的正式表，只进开销/精度对照证据。
