# 12 · 四折 LSO 基线与 2026-10-24 BVH24 适配（2026-11-09）

登记对象：MotionPRO、FPP-Net、PoseTransOpt（MMVP 链）。触发原因：2026-10-24 raw 换代
（BVH24 / `smpl_new`）后，2026-10-22 生产的 MotionPRO 输入树与 FPP `sub_info` 过期；
四折 LSO 要求两基线在**同一份 raw、同一份 GT** 上与 V8 对比。

## 1. raw 换代与已核验一致项

- 触觉正典 `hf-raw/pressure` v3.1 `processed48`（2026-10-24）；`shared/facts` 的
  `pressure_48` 与之逐元素一致（采样 8 会话 0 差）。
- MMVP `shared/representations/tactile/mmvp_31x11/v1` 与当前 facts 的 4x12→31x11
  映射逐元素一致（采样 8 会话 max|Δ|=0）。
- BVH 正典改为 `motion_smpl24_blender_world_m.bvh`（BVH24，z-up，m；
  `pelvis/left_hip/.../left_foot/left_foot_EndSite0`，**无 toe 关节**）。
- SMPL 正典为 `*_smpl_new` MoSh++；评估 GT 与 V8 均经 manifest `smpl_path` →
  `hf-raw/smpl` → `smpl_new`（S11011 实测 resolve 目标）。

## 2. 代码偏离（主库工具，非 Baselines 原生模型代码）

### 2.1 MotionPRO 关节名归一化

原生行为：`AnysoleWorkspace/tool/adapters/MotionPRO/adapter.py` 的 `_joint_index` /
`_foot_signal` / `_f6_signals` 只匹配 `LeftFoot` / `LeftToeBase`（BVH-23 命名）。

本地行为：名称比较前做 `lower().replace("_", "")`；`toe` 无精确命中时取该脚
`*_EndSite*` 作为 toe（BVH24 的 End Site 即脚趾端）。旧 BVH-23 名称仍精确命中，
**行为不变**。

原因：BVH24 下旧代码直接抛 `no left foot joint in BVH names`，无法生成 carpet / F6。

证据：140/140 会话重建通过；空毯 0、触觉非零丢失 0；采样会话新旧 contact 差
（S10112 204/4220 帧·脚）说明旧树确实为旧 BVH 产物。

### 2.2 新输入树（不覆盖旧树）

- `AnysoleWorkspace/model_inputs/MotionPRO/adapter_v3_bvh24/cam3`：carpet / contact /
  smpl / keypoints / frame_id 全部由当前 facts 重建；`feature_hrnet.pth` 链接旧
  `adapter_v1`（RGB-only，不受 mocap 换代影响）。共 140 会话（canonical 136 +
  四折独有 S11051/S11053/S7053/S8053）。
- 任务配置：`Baselines/MotionPRO/config/task/imagepressure2smpl_carpet_v3_bvh24_cam3.yaml`
  （geometry sha `34969f…`，shape 420×135，entry 252×108）。
- `AnysoleWorkspace/model_inputs/FPP-Net/adapter_v2_bvh24`：session 树链接旧适配器，
  `sub_info.npy` 用新 BVH 重算（差异：S13 +5.33%、S7 +2.09%、S14 +1.62%、
  S11 +1.06%、S5 +0.25%，其余≈0）；四折 `dataset_split_temporal5_<fold>.npy`。
- FPP 配置：`Baselines/VP-MoCap/FPP-Net/configs/temporalKPSMPLCont_series5_mlp_<fold>.yaml`
  （datadir/tv_fn/prediction_root/checkpoint 名逐折隔离）。

### 2.3 PoseTransOpt 逐折隔离

原生 `build_inputs.py` / `run_full_mmvp.py` 的输入/输出根为常量。新增参数
`--input-root` / `--fpp-root`（adapter）与 `--input-root` / `--output-root`
（run_full_mmvp），默认值保持原行为；`export_baseline_motion.py` 新增
`--native-root`，且 `--variant vp_mocap_<fold>` 时 VP-MoCap 预测落
`predictions/<variant>/eval_motion/`。原因：同一会话在不同折由不同 FPP 模型产生，
不能共用 `predictions/eval_motion/`。

## 3. 训练/评测口径

- MotionPRO：原生 1000 epoch、batch 16、val 选 `imagepressure2smpl_best.pth`；
  训练结束自动 test + 写统一契约。逐折 `split_csv=splits_test_*_val_*.csv`。
- FPP-Net：原生 1410 epoch、batch 32、`latest`（每 100 epoch 落盘）；逐折训练/推理。
- PoseTransOpt：原生 `max_iter=2001` 逐帧优化，逐折 `fpp_predictions_<fold>` 输入。
- 评估：`r_test2_compare.py --split <fold> --split-csv crossfit_woS13/<fold>.csv
  --models-config .../motionpro_mmvp_registry_<fold>.yaml --write-model-metrics`；
  schema v2 落 `results/baselines/<Model>/metrics/<fold>_comparison.json`。
- E2 导出：`results_display/script/e2_crossfit_export.py --with-baselines`；
  MotionPRO canonical 单折行仅在四折不全时保留。

## 4. 早停（2026-11-10 追加）

MotionPRO 原生 1000 epoch，只有 ReduceLROnPlateau（patience 5）没有早停。四折实测：

| 折 | val 最优 epoch | 之后到 kill 的 epoch | 是否再改善 |
|---|---|---|---|
| fS5S6S11 | 118 | 731 | 否 |
| fS5S11S12 | 86 | 698 | 否 |
| fS6S7 | 106 | ~150 | 否 |
| fS5S6S8 | 110 | ~150 | 否 |

旧链（10-23 canonical）同样是 epoch 45 最优、到 505 不再改善。结论：1000 epoch 中约
850–900 epoch 是纯过拟合（train loss 继续降、val 不动），best checkpoint 早已选出。

处置（2026-11-10 用户裁定，最终口径）：**按 LR 触底早停，用 last checkpoint，不取
val-best**。规则：`optimizer.param_groups[0]['lr'] < 5e-8` 时停止；`train_frappe.py`
新增 `early_stop_lr_floor`（默认 0 = 原生行为；v3 任务配置设 5e-8）。四折实际停止
epoch：fS5S6S11 731（lr 1.22e-8）、fS5S11S12 698（1.22e-8）、fS6S7 145（4.88e-8）、
fS5S6S8 111（2.44e-8，`_112` 被 kill 写坏，用最后一个有效且触底的 ckpt）。test 与
统一导出均显式指向这些 last ckpt。

FPP 同样用 LR-floor：`--early-stop-lr-floor 5e-8`，停止后取 `latest`
（1099/999/999/899，LR 1e-9/1e-8，均已触底）。注意：LR-floor 检查必须独立于
`estop_patience`（原实现嵌在 patience 块内，已修）。

## 6. 基线类型（2026-11-11 用户裁定）

按**推理时实际输入**分类，训练期的 T/M 监督不改变基线类型：

| 基线 | 类型 | 依据 |
|---|---|---|
| MotionPRO | **VT2M（U@VT）** | 推理输入 = HRNet 图像特征 + 压力毯（真实 T）；M 只作训练监督 |
| MMVP / VP-MoCap（FPP-Net + PoseTransOpt） | **V2M（U@V）** | 推理只读视觉：RGB→RTMPose keypoints、CLIFF、FPP 预测接触、DepthPro 模板；真实 T/M 只用于训练/评估。等价主模型 U@V |
| MMVP pressure_toolkit | VT2M（U@VT） | 推理读 insole |
| Step2Motion | T2M（U@T） | 推理只读触觉/IMU |
| FPP-Net 单模型（V2T） | V2T | 输入视觉、输出接触/压力，不作运动行 |

注册表 `results_display/models_modes.yaml` 已把 `MMVP_VP-MoCap` 从 VT2M 移到
V2M；四折 per-fold registry 同步改为 `mode: V2M`。E2 表因此显示 VP-MoCap
`U@V`、MotionPRO `U@VT`。
